1. WHAT THIS PROJECT IS
--------------------------------------------------------------------------------
A production-grade, HEADLESS NLP pipeline that runs end-to-end with ZERO user
intervention (`python main.py`) and produces a comprehensive, self-contained
HTML report (model metrics, confusion matrix, RAG evidence examples, data
quality insights). A Streamlit web dashboard with a warm, creamy-light theme
makes the results accessible to stakeholders who are not comfortable with the
command line.

The pipeline is modular, reproducible and fault tolerant: if a data source is
temporarily unavailable it falls back to cached data or gracefully skips that
domain.

It covers two safety-critical domains:
  - AVIATION   : NASA ASRS (Aviation Safety Reporting System) incident reports
  - POWER GRID : NERC (North American Electric Reliability Corporation) event
                 analysis reports

It performs, end to end:
  1. Live data collection (fetch / refresh, idempotent)
  2. Text preprocessing (NLTK)
  3. Classification model training (TF-IDF + SGD/log-loss with GridSearchCV)
  4. Evaluation (classification report + confusion matrix + plots)
  5. Batch RAG explainability (semantic evidence retrieval for the test set)
  6. Self-contained HTML report generation (Jinja2)
  7. Interactive Streamlit dashboard for stakeholders


--------------------------------------------------------------------------------
2. PROJECT GOALS
--------------------------------------------------------------------------------
  - Build a professional, observable, repeatable NLP solution over real public
    safety data that produces tangible outputs (HTML report + web dashboard).
  - Zero user intervention: one command runs the entire pipeline.
  - Every prediction must be explainable: RAG retrieves the top-3 most similar
    historical reports as evidence (an auditable explanation by example).
  - Model robustness: cross-validation (StratifiedKFold) + hyperparameter
    tuning (GridSearchCV over alpha and class_weight).
  - Fault tolerance: per-domain graceful fallback to cached data.
  - A "keyless" data assistant (no LLM, no API key) that audits data quality
    and safety criticality with pandas.

3. DATA SOURCES
--------------------------------------------------------------------------------
The dataset is collected LIVE from public sources every run (or reused from a
cache) — nothing is pre-baked into the repository.

  DOMAIN      | SOURCE                                   | WHAT IS DOWNLOADED
  ------------+------------------------------------------+--------------------
  Aviation    | NASA ASRS via Hugging Face datasets-server| 2,000 real incident
              | (elihoole/asrs-aviation-reports)         | reports with expert
              |                                          | anomaly labels from
              |                                          | Events_Anomaly
  Power grid  | NERC Event Analysis reports (public PDFs)| 12 real grid-incident
              |                                          | post-mortems
              |                                          | (Northeast 2003
              |                                          | blackout, Hurricane
              |                                          | Sandy, San Fernando
              |                                          | disturbance, ...)

Aviation: streamed row-by-row from the Hugging Face datasets-server API in
paginated batches of 100. Narrative text from "Report 1_Narrative", expert
anomaly labels from "Events_Anomaly" (multi-label strings split to the primary
category; rare categories bucketed as "Other").

Power grid: 12 public NERC PDFs are downloaded (cached in data/raw/), text is
extracted with pypdf and split into incident narratives with NLTK sentence
tokenization (~5 sentences per chunk).

Both sources are cleaned (dedupe, drop empty labels, drop very short rows,
collapse whitespace) and merged into one Domain-tagged dataset saved at:
    data/real_safety_dataset.csv
(~3,700 cleaned reports: 2,000 aviation + ~1,700 power-grid narratives)

The 12 NERC reports (from config.py):
  - Power Grid - Northeast Blackout 2003
  - Power Grid - Hurricane Sandy
  - Power Grid - Hurricane Harvey
  - Power Grid - Hurricane Irma
  - Power Grid - San Fernando Disturbance
  - Power Grid - January 11 Oscillation Event
  - Power Grid - South Central Cold Weather
  - Power Grid - Solar PV Disturbance 2018
  - Power Grid - Northeast Snowstorm 2011
  - Power Grid - Arizona Southern California Outage
  - Power Grid - IBR Disturbances Western Interconnection
  - Power Grid - January 2025 Arctic Events

4. PIPELINE ARCHITECTURE
--------------------------------------------------------------------------------
  data/real_safety_dataset.csv   (NASA ASRS + NERC, ~3,700 domain-tagged reports)
        |
  [1/6] FETCH   (live: ASRS datasets-server + NERC PDFs -> clean -> merge by domain)
        |
  [2/6] PREPROCESS  (NLTK tokenize -> stopword removal -> lemmatize, per-document)
        |
  [3/6] TRAIN   (TF-IDF bigrams, max_features=5000 -> SGD/log-loss,
        |        GridSearchCV: alpha x class_weight, StratifiedKFold CV,
        |        best model + vectorizer saved to data/*.pkl)
  [4/6] EVALUATE (classification report, confusion-matrix heatmap,
        |         class-distribution plot -> data/plots/*.png, persisted metrics)
  [5/6] RAG EXPLAINABILITY (sample of the test set -> predict each report ->
        |                     batch cosine similarity vs all training
        |                     narratives -> top-3 evidence spans)
  [6/6] HTML REPORT (Jinja2 self-contained page -> reports/pipeline_report.html)
        |
  [Web] STREAMLIT DASHBOARD (app_streamlit.py, creamy light theme)

STEP DETAILS
  1. DATA_FETCHER (src/data_fetcher.py)
     - _fetch_aviation(): streams ASRS rows from datasets-server; keeps rows
       with a narrative AND a non-empty anomaly label; top-15 categories kept,
       the rest merged into "Other".
     - _fetch_power(): downloads each NERC PDF, parses with pypdf, cleans
       header/footer noise lines, sentence-tokenizes with NLTK and builds
       ~5-sentence narrative chunks tagged with the event label.
     - Graceful SSL fallback (some corporate / Python CA stores fail).
     - Merges both domains into one "domain"-tagged DataFrame and saves CSV.

  2. PREPROCESSOR (src/preprocessor.py)
     - NLTK: tokenize -> lowercase -> keep alphanumeric -> remove English
       stopwords -> WordNet lemmatize. NLTK corpora auto-download on first run.

  3. TRAINER (src/trainer.py)
     - Per-document NLTK preprocessing with progress logging.
     - Stratified train/test split (80/20, random_state=42).
     - TfidfVectorizer: stop_words="english", max_features=5000,
       ngram_range=(1, 2) — bigrams capture domain terms like "gear down" /
       "load shed" / "transmission line".
     - GridSearchCV over SGDClassifier(loss="log_loss") hyperparameters
       (alpha in [1e-5, 1e-4, 1e-3] x class_weight in [None, "balanced"])
       using StratifiedKFold(3) and f1_weighted scoring. The test set is never
       used for tuning.
     - Saves best model + vectorizer (joblib) and training_config.json.

  4. EVALUATOR (src/evaluator.py)
     - Vectorizes the test set and predicts with the best model.
     - Per-class classification report (precision/recall/f1/support).
     - Confusion-matrix heatmap (normalised) + top-N class-distribution bar
       chart, saved as PNGs under data/plots/.
     - Persists classification_report.txt/.csv and metrics.json for the
       dashboard.

  5. RAG_EXPLAINER (src/rag_explainer.py)
     - batch_rag(): samples test reports; for each, predicts the class and
       computes cosine similarity against ALL training narratives in batches;
       returns the top-3 most similar historical reports as evidence.
     - build_index() + explain_text(): fast single-query retrieval for the
       interactive dashboard (the corpus matrix is precomputed once).

  6. REPORT_GENERATOR (src/report_generator.py)
     - Jinja2 template builds a self-contained HTML page with: project summary
       + dataset statistics, data-quality audit, best hyperparameters,
       per-class metrics table, embedded confusion-matrix and class
       distribution plots (base64), and RAG examples with similarity bars.
     - Saves as reports/pipeline_report.html — opens in any browser.

  7. ANALYST (src/analyst.py)
     - Keyless data assistant (quality / safety / classes / risk scanning).
     - See section 5.


--------------------------------------------------------------------------------
5. WEB DASHBOARD (STREAMLIT)
--------------------------------------------------------------------------------
Launch with:  streamlit run app_streamlit.py   (opens http://localhost:8501)

A warm, creamy-light themed dashboard (background #FFF8F0, headings #5C4033,
buttons #F5E6D3) for stakeholders who prefer a browser over the terminal. It
loads the artifacts produced by `python main.py` and serves live predictions.

| Tab                  | Content                                                        |
|----------------------|----------------------------------------------------------------|
| Overview             | dataset size, domain split, class-distribution chart, sample rows |
| Model Performance    | metrics, per-class classification table, confusion-matrix & distribution plots |
| RAG Explorer         | paste an incident -> predicted class + top-3 evidence with similarity bars |
| Data Assistant       | keyless quality / safety / class insights and risk-phrase scanning |

The theme lives in .streamlit/config.toml and custom CSS in the app.

6. FAULT TOLERANCE & IDEMPOTENCY
--------------------------------------------------------------------------------
  - If data/real_safety_dataset.csv already exists, the fetch step is skipped
    entirely (idempotent). Delete the CSV or pass --force-refresh to download.
  - Each domain is fetched independently. If one source fails, the pipeline
    falls back to the cached rows for that domain, or gracefully skips it with
    a warning.
  - If both sources fail, the cached dataset is reused (if present).
  - Downloaded NERC PDFs are cached in data/raw/ so re-fetches are fast.
  - Legacy column names (Narrative / human_factors_groundtruth / Domain) are
    auto-normalised to the canonical lowercase schema (narrative/label/domain).
  - All steps log to the console AND pipeline.log.

7. HEADLESS CLI
--------------------------------------------------------------------------------
  python main.py --fetch-only       (not implemented; see flags)
  python main.py --no-fetch         # skip fetching, require cached CSV
  python main.py --force-refresh    # re-download data
  python main.py --no-rag           # skip RAG explainability
  python main.py --samples N        # RAG test samples (default 100)

Each src module is also runnable directly (e.g. python src/data_fetcher.py).

11. HOW TO RUN
--------------------------------------------------------------------------------
  pip install -r requirements.txt
  python main.py                          # full pipeline, one command
  # open reports/pipeline_report.html in a browser

  streamlit run app_streamlit.py          # web dashboard
  # open http://localhost:8501

First run auto-downloads the NLTK corpora (stopwords, punkt, wordnet) and the
live datasets; allow 2-5 minutes. Subsequent runs reuse the cache.

12. RESULTS
--------------------------------------------------------------------------------
  - Dataset : ~3,700 cleaned reports — 2,000 NASA ASRS aviation narratives
              (expert anomaly labels) + ~1,700 power-grid narratives extracted
              from 12 public NERC event-analysis PDFs.
  - Model   : ~70% weighted F1 / ~71% accuracy over 28 classes with TF-IDF +
              SGD/log-loss and GridSearchCV (best: alpha=1e-4, balanced class
              weights, CV F1 0.690). Aviation classes are noisy and
              imbalanced; power-grid classes like 'Northeast Blackout 2003'
              are near-perfect (F1 0.98).
  - RAG     : aviation queries predict ATC/conflict categories with aviation
              evidence; power-grid queries predict NERC event categories with
              grid-incident evidence — every prediction is auditable.
  - Outputs : reports/pipeline_report.html (self-contained) + Streamlit
              dashboard; all metrics, plots and examples in one place.

13. RESEARCH GAPS ADDRESSED
--------------------------------------------------------------------------------
  - Gap 4 (black-box provenance): RAG explainability module provides an audit
    trail — the report and dashboard show which historical reports influenced
    each prediction.
  - Gap 2 (edge deployment): the lightweight TF-IDF + SGD model is far smaller
    than LLMs and deploys to constrained devices easily.
  - Gap 3 (cross-domain taxonomy): aviation and power-grid narratives share one
    TF-IDF vocabulary, so the model distinguishes domains while RAG evidence
    surfaces genuine cross-domain similarities when they exist.
  - Gap 1 (physical constraints): the modular design allows swapping the
    classifier output for a solver-based constraint verifier.
