1. WHAT THIS PROJECT IS
--------------------------------------------------------------------------------
A fully terminal-driven demonstration of a REAL NLP pipeline over real
safety-incident data. It is built as an interactive TUI (Textual) with no
browser and no fake animation — every progress bar is driven by actual work
(rows downloaded, documents preprocessed, minibatches fitted).

The pipeline covers two safety-critical domains:
  - AVIATION   : NASA ASRS (Aviation Safety Reporting System) incident reports
  - POWER GRID : NERC (North American Electric Reliability Corporation) event
                 analysis reports

It performs, end to end:
  1. Live data collection (fetch / refresh)
  2. Text preprocessing (NLTK)
  3. Classification model training (TF-IDF + SGD/logistic regression)
  4. RAG explainability (semantic evidence retrieval)
  5. Data quality / safety analysis (keyless "NLP data assistant")


--------------------------------------------------------------------------------
2. PROJECT GOALS
--------------------------------------------------------------------------------
  - Demonstrate a complete, real NLP pipeline over real public safety data.
  - Show every NLP stage visually inside the terminal with genuine progress
    (no staged animation).
  - Work on two different domains (aviation + power grid) merged into one
    domain-tagged dataset, proving the pipeline generalizes.
  - Make model predictions explainable: RAG retrieves the top-3 most similar
    historical reports as evidence for every classification.
  - Provide a "keyless" data assistant (no LLM, no API key) that audits data
    quality and safety criticality with pandas.
  - Stay scriptable via a headless CLI for CI / scripting.

3. DATA SOURCES
--------------------------------------------------------------------------------
The dataset is collected LIVE from public sources every run — nothing is
pre-baked into the repository.

  DOMAIN      | SOURCE                                   | WHAT IS DOWNLOADED
  ------------+------------------------------------------+--------------------
  Aviation    | NASA ASRS via Hugging Face datasets-server| 2,000 real incident
              | (elihoole/asrs-aviation-reports)         | reports with expert
              |                                          | anomaly labels from
              |                                          | Events_Anomaly
  Power grid  | NERC Event Analysis reports (public PDFs)| 12 real grid-incident
              |                                          | post-mortems
              |                                          | (Northeast 2003
              |                                          | blackout, Hurricane
              |                                          | Sandy, San Fernando
              |                                          | disturbance, ...)

Aviation: streamed row-by-row from the Hugging Face datasets-server API in
paginated batches of 100. Narrative text from "Report 1_Narrative", expert
anomaly labels from "Events_Anomaly" (multi-label strings split to the
primary category; rare categories bucketed as "Other").

Power grid: 12 public NERC PDFs are downloaded, text is extracted with pypdf
and split into incident narratives with NLTK sentence tokenization (~5
sentences per chunk).

Both sources are cleaned (dedupe, drop empty labels, drop very short rows,
collapse whitespace) and merged into one Domain-tagged dataset saved at:
    data/real_safety_dataset.csv
(~3,700 cleaned reports: 2,000 aviation + ~1,700 power-grid narratives)

If a source is unreachable, the run falls back to the cached copy instead of
dying.

The 12 NERC reports (from pipeline/paths.py):
  - Power Grid - Northeast Blackout 2003
  - Power Grid - Hurricane Sandy
  - Power Grid - Hurricane Harvey
  - Power Grid - Hurricane Irma
  - Power Grid - San Fernando Disturbance

4. PIPELINE ARCHITECTURE
--------------------------------------------------------------------------------
  data/real_safety_dataset.csv   (NASA ASRS + NERC, ~3,700 domain-tagged reports)
        |
  1. FETCH   (live: ASRS datasets-server + NERC PDFs -> clean -> merge by Domain)
        |
  2. PREPROCESS  (NLTK tokenize -> stopword removal -> lemmatize, per-document)
        |
  3. TRAIN   (TF-IDF bigrams -> SGD/log-loss, balanced class weights,
        |    minibatch partial_fit over 3 epochs, saved as data/*.pkl)
  4. RAG EXPLAINER (vectorize new report -> predict category ->
                    batch cosine similarity vs all reports -> top-3 evidence)
        |
  5. NLP DATA ASSISTANT (pandas insights: quality audit + domain + criticality)

STEP DETAILS
  1. FETCH_DATA (pipeline/fetch_data.py)
     - _fetch_aviation(): streams ASRS rows from datasets-server; keeps rows
       with a narrative AND a non-empty anomaly label; top-15 categories kept,
       the rest merged into "Other".
     - _fetch_power(): downloads each NERC PDF, parses with pypdf, cleans
       header/footer noise lines, sentence-tokenizes with NLTK and builds
       ~5-sentence narrative chunks tagged with the event label.
     - Graceful SSL fallback (some corporate / Python CA stores fail).
     - Merges both into one DataFrame with a "Domain" column and saves CSV.

  2. PREPROCESS (pipeline/preprocess.py)
     - NLTK: tokenize -> lowercase -> keep alphanumeric -> remove English
       stopwords -> WordNet lemmatize. NLTK corpora auto-download on first run.

  3. TRAIN_MODEL (pipeline/train_model.py)
     - Per-document NLTK preprocessing with real progress
       (e.g. "PREPROCESSING 412/2035 (NLTK)").
     - TfidfVectorizer: stop_words="english", max_features=3000,
       ngram_range=(1, 2) — bigrams capture domain terms like "gear down" /
       "load shed" / "transmission line".
     - Stratified train/test split (80/20, random_state=42).
     - SGDClassifier with loss="log_loss" (mathematically the same objective
       as logistic regression, but trains incrementally via partial_fit so the
       progress bar reflects real minibatch fits).
     - 3 epochs, batch size 256, shuffled order, balanced class weights.
     - Evaluates with classification_report and saves model + vectorizer as
       data/safety_model.pkl and data/tfidf_vectorizer.pkl (joblib).

  4. RAG_EXPLAINER (pipeline/rag_explainer.py)
     - Loads dataset + trained artifacts.
     - Preprocesses the new report, TF-IDF vectorizes it, predicts its risk
       category.
     - Embeds the whole historical corpus in real batches of 200 and computes
       cosine similarity batch-by-batch (real progress).
     - Returns top-3 most similar historical reports (with similarity %, label
       and domain) as in-context evidence for the prediction.

  5. ANALYST (pipeline/analyst.py)
     - Keyless assistant. See section 6.


--------------------------------------------------------------------------------
5. THE TERMINAL UI (Textual TUI)
--------------------------------------------------------------------------------
Launch with:  python app.py

Numbered menu (always available, re-open with 'm'):

  1 · Fetch / Refresh dataset       4 · RAG explainer
  2 · View datasets                 5 · NLP data assistant
  3 · Train model                   6 · Pipeline log
                                     7 · Exit

WHAT EACH OPTION DOES
  1. Fetch / Refresh — live-downloads the two real sources with real streaming
     progress, then shows the cleaned, domain-tagged result.
  2. View datasets — lists every CSV in data/ in a dropdown and opens the
     selected one: raw narrative preview table (with domain) + anomaly-category
     distribution. Any dataset file you add later appears here automatically.
  3. Train model — full NLP training chain with visible real progress:
     NLTK preprocessing -> TF-IDF vectorization -> stratified split -> SGD
     (log-loss) minibatch training -> evaluation -> classification report.
  4. RAG explainer — paste a new incident report; the system predicts its risk
     category (aviation or power-grid) and retrieves the top-3 most similar
     historical reports as evidence with similarity bars (block chars + %) and
     the domain of each match.
  5. NLP data assistant — keyless analyst working on the loaded dataset.
  6. Pipeline log — full console output of every step, live.
  7. Exit — close the TUI.

WHAT THE PROGRESS BAR IS REALLY SHOWING (every % maps to real work):
  - Fetch   : advances as ASRS rows are actually streamed and as each NERC PDF
              is downloaded and parsed.
  - Train   : advances per DOCUMENT during NLTK preprocessing, then per
              MINIBATCH while the SGD/logistic classifier is fitted.
  - RAG     : advances per real cosine-similarity batch.

The pipeline status bar at the top shows which steps are done:
  [OK] 1 FETCH  [OK] 2 TRAIN  [OK] 3 EXPLAIN


--------------------------------------------------------------------------------
6. NLP DATA ASSISTANT (option 5)
--------------------------------------------------------------------------------
A keyless analyst — everything computed from the actual dataset with pandas,
no LLM, no API key.

Quick buttons: Summary, Quality/issues, Safety/critical, Classes.

Free-form commands:
  - quality / issues        what is right and wrong in the data (missing
                            values, duplicate narratives, very short reports,
                            class imbalance, 'Other' bucket coverage)
  - safety / critical       safety-criticality breakdown (critical/high/medium
                            via keyword rules), domain split (Aviation vs
                            Power Grid) and the most frequent critical
                            categories
  - classes                 anomaly-category distribution
  - analyze <text>          scans a narrative for high-risk phrases
                            (TCAS RA, CFIT, NMAC, wake vortex, bird strike,
                             fire/smoke, fuel, fatigue, weather, unstabilized
                             approach, medical, passenger misconduct, ...)
  - summary                 dataset row/column counts + quality report

--------------------------------------------------------------------------------
For scripting / CI (no TUI):

  python app.py --fetch                     # live-download both domains
  python app.py --train                     # train + evaluate the model
  python app.py --explain "<incident text>" # classify + RAG evidence

Each pipeline module is also runnable directly:
  python pipeline/fetch_data.py
  python pipeline/train_model.py
  python pipeline/rag_explainer.py

10. HOW TO RUN
--------------------------------------------------------------------------------
  pip install -r requirements.txt
  python app.py                          # interactive TUI (numbered menu)

Headless:
  python app.py --fetch                  # live-download both domains
  python app.py --train                  # train the model
  python app.py --explain "engine fire right after takeoff"

Press a number to select a menu option (or 'm' to re-open the menu at any
time, 'q' to quit, Esc to drop to the console).

11. RESULTS
--------------------------------------------------------------------------------
  - Dataset : ~3,700 cleaned reports — 2,000 NASA ASRS aviation narratives
              (expert anomaly labels) + ~1,700 power-grid narratives extracted
              from 12 public NERC event-analysis PDFs.
  - Model   : ~68% weighted accuracy over 28 classes with TF-IDF + SGD/log-loss
              (aviation classes are noisy and imbalanced; power-grid classes
              like 'Northeast Blackout 2003' are cleanly separated).
  - RAG     : aviation queries predict ATC/conflict categories with aviation
              evidence; power-grid queries predict NERC event categories
              (e.g. 'Power Grid - Northeast Snowstorm 2011') with grid-incident
              evidence — both with real similarity bars.
